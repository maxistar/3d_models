## Context

В репозитории есть несколько типов OpenSCAD-файлов: самостоятельные модели, части одной модели, библиотеки и исходники, требующие нестандартной версии OpenSCAD. Текущий `scripts/process.sh` обрабатывает все `.scad` в выбранном каталоге и не различает эти категории.

Обычным правилом группировки будет общий префикс имени файла. Однако `honeycomb` уже является единым проектом с исторически разными именами компонентов, поэтому для него требуется явное проектное исключение. `RuggedBoxV1.scad` должен быть исключён из автоматической обработки из-за внешнего происхождения и несовместимости с обычным процессом сборки.

## Goals / Non-Goals

**Goals:**

- привести очевидные группы `blocknote` и `helping_hand` к единому соглашению об именах;
- отделить служебные исходники от моделей через префикс `_`;
- добавить воспроизводимый blacklist для отдельных файлов и каталогов;
- заставить batch-генерацию обрабатывать только разрешённые исходники;
- сохранить существующие страницы сайта и проверить пути используемых ими STL;
- оставить `honeycomb` единым проектом без массового переименования его компонентов.

**Non-Goals:**

- автоматическое создание Astro-страниц по содержимому каталогов;
- изменение геометрии моделей;
- исправление или адаптация `RuggedBoxV1` под текущую версию OpenSCAD;
- массовая нормализация всех исторических имён в каталоге `honeycomb`;
- ввод полноценного манифеста с описанием каждой модели.

## Decisions

### 1. Префикс — стандартная группировка, проектное исключение — явное

Файлы с общим смысловым префиксом считаются одной группой по умолчанию. Для `honeycomb` сохраняется единая проектная группа, заданная отдельным правилом, потому что имя каждого компонента не обязано содержать `honeycomb`.

Это оставляет автоматическое правило простым, но позволяет не разрушать уже существующую структуру большого проекта. Полностью полагаться только на анализ зависимостей не будем: зависимости нужны компилятору, но не определяют структуру страниц.

### 2. Служебные исходники определяются именем

Любой файл, имя которого начинается с `_`, автоматически исключается из генерации STL/PNG и из будущего каталога моделей. Так библиотека `honeycomb_element.scad` может быть переименована в `_honeycomb_element.scad`, после чего ссылки `use` должны использовать новое имя.

Альтернатива — отдельный список всех библиотек — отвергнута: он будет легко устаревать при добавлении новых служебных файлов.

### 3. Blacklist хранится в корне репозитория

В корне проекта вводится файл `.modelignore` с пустыми строками, комментариями и путями относительно корня репозитория. На первом этапе он содержит точные пути к `RuggedBoxV1.scad` в известных каталогах. Формат должен допускать добавление отдельных файлов и каталогов без изменения скрипта.

Путь, а не только basename, используется намеренно: одинаковые имена могут встречаться в разных каталогах и иметь разный статус.

### 4. Фильтрация применяется до генерации

`scripts/process.sh` сначала формирует список `.scad`, затем отбрасывает `_*.scad` и пути из `.modelignore`, и только после этого проверяет STL/PNG и запускает OpenSCAD. Исключённые исходники считаются намеренно пропущенными, а не ошибочными отсутствующими артефактами.

### 5. Имена исходника и артефактов синхронизируются

При переименовании `blocknote` и `helping_hand` исходник, STL, PNG и ссылки на `use/include` должны использовать одинаковую базовую часть имени. Astro-страницы обновляются на канонические пути, а URL самих страниц сохраняются.

Старые прямые пути к STL требуют отдельной проверки во время миграции. Если хостинг не предоставляет безопасных алиасов, переименование опубликованных артефактов должно быть выполнено с явным решением о совместимости, а не молча.

## Risks / Trade-offs

- [Переименование STL ломает внешние прямые ссылки] → проверить фактические потребители старых путей и сохранить совместимость алиасами либо явно принять миграцию.
- [Blacklist может скрыть нужную модель] → использовать точные относительные пути, комментарии с причиной и отдельную проверку списка исключений.
- [Префикс не всегда отражает проект] → оставить явное исключение для `honeycomb` и не пытаться вывести все отношения из `use/include`.
- [Служебный файл может случайно получить STL в рабочем каталоге] → генератор не удаляет такой артефакт автоматически; отдельная проверка должна выявлять устаревшие outputs.
- [Генерация PNG требует OpenGL-контекста] → наличие PNG не является обязательным условием переименования источника, если до миграции у него уже не было превью; проверка сохраняет существующие превью и отдельно фиксирует ограничения headless-окружения.
- [RuggedBoxV1 присутствует в нескольких каталогах] → занести каждый фактический путь в blacklist, не полагаться на одно совпадение имени.

## Migration Plan

1. Зафиксировать текущие ссылки сайта и список файлов, которые будут переименованы.
2. Добавить blacklist и правило `_*.scad` без удаления существующих артефактов.
3. Переименовать библиотеки и очевидные модельные группы, обновив внутренние и сайт-ссылки.
4. Перегенерировать только затронутые STL/PNG и проверить, что исключённые модели не запускаются.
5. Проверить сборку сайта и все существующие страницы.

При проблеме миграцию можно откатить возвратом имён исходников и ссылок; изменение не затрагивает формат STL или геометрию.

## Open Questions

- На текущем этапе старые имена STL не сохраняются как алиасы: все найденные потребители находятся внутри репозитория и обновляются на канонические пути.
- `.modelignore` поддерживает точные пути; поддержку glob-шаблонов можно добавить позднее при появлении такой потребности.
- `honeycomb_element.scad` переименовывается в `_honeycomb_element.scad` в рамках этого change.
