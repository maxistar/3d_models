## Why

Структура исходных моделей сейчас отражает историю разработки, но не всегда позволяет однозначно определить, какие файлы относятся к одному проекту, какие являются служебными, а какие нельзя собирать стандартной версией OpenSCAD. Это мешает безопасно автоматизировать генерацию STL и в дальнейшем строить страницы сайта из исходников.

Сейчас подходящий момент зафиксировать соглашения и убрать очевидные неоднозначности, пока автоматическое построение каталога моделей ещё не реализовано.

## What Changes

- Зафиксировать соглашение, по которому общий префикс по умолчанию определяет группу файлов для одной страницы проекта.
- Сохранить `honeycomb` как единый проект, несмотря на разные префиксы его компонентов.
- Нормализовать имена файлов группы `blocknote`, добавив префикс `blocknote_` к её частям.
- Нормализовать имена двух частей `helpinghand`, которые сейчас не соответствуют префиксу `helping_hand`.
- Ввести правило, по которому файлы, начинающиеся с `_`, считаются служебными и не должны автоматически порождать STL.
- Добавить явный blacklist для несовместимых или намеренно исключённых исходников, включая `RuggedBoxV1.scad`.
- Изменить batch-генерацию так, чтобы она пропускала служебные и заблокированные исходники без сообщения об ошибке отсутствующего STL.
- Не менять пока алгоритм автоматического создания страниц сайта; текущие страницы и URL должны продолжить работать.

## Capabilities

### New Capabilities

- `model-source-organization`: соглашения об именовании, группировке проектов и явных исключениях для исходных моделей.

### Modified Capabilities

- `ascii-stl-export`: batch-экспорт учитывает служебные файлы и blacklist при выборе исходников для генерации.

## Impact

- Исходные файлы OpenSCAD в каталогах `openscad/blocknote` и `openscad/helpinghand` будут переименованы вместе с соответствующими ссылками и STL/PNG-артефактами.
- Скрипт `scripts/process.sh` получит правила фильтрации исходников и чтения blacklist.
- Появится репозиторный файл конфигурации исключений моделей.
- Существующие Astro-страницы, опубликованные URL и пути STL должны остаться совместимыми.
- `RuggedBoxV1.scad` не будет участвовать в автоматической генерации и публикации.
